## 0. 한 줄 판정

**피드백이 맞다. "어떤 이탈부터 볼까요?" 선택은 사용자 필요가 아니라 비용·시간을 줄이려던 구현 흔적이다.**
HAZOP 은 원래 가이드워드 전부를 도는 방법이라, 기본을 "전체 가이드워드 생성"으로 바꾸고 결과를 **보는 방법**(워크시트 순서 · 가이드워드별 · 파라미터별 · 공정 전체 노드 순서)을 고르게 한다.
특정 가이드워드 하나만 빠르게 확인하고 싶은 실무 상황을 위해 **"가이드워드 하나만 빠르게"**를 보조 실행으로 남긴다(관람객용·부스용 기능이 아니다 — 화면 어디에도 그렇게 쓰지 않는다).
대가는 기본 실행 1회 **약 2.5분 · 약 $0.8**(지금 빠른 실호출의 약 2배 시간 · 6배 비용)이며, 발표 대본·포스터·부스 예산을 같이 고친다.

**사용자 결정(10/8 밤)**: ① 포스터도 이 변경에 맞춰 10/12 마감 전에 다시 고친다 ② 빠른 보기는 남기되 **실무 기능**으로 — 특정 가이드워드만 빠르게 보고 싶을 때 쓰는 보조 실행이며, "부스용" 같은 표현은 화면·문서·포스터 어디에도 쓰지 않는다.

## 1. 피드백 원문과 판단

> 왜 이탈을 선택해야하는지 모르겠음 → 다 필요하다면 그냥 다 있으면 좋은거고, 순서를 봐야하는거면 각각 분류를 해서 노드 순서별로 보는거면 노드 순서 별로 나오는 것이 좋고 이탈을 볼거면 이탈별로 어떻게 나오는지 생겼으면 좋겠다

| 피드백 | 판단 | 근거 |
|---|---|---|
| 선택이 왜 필요한지 모르겠다 | **수용.** 선택을 없앤다 | 선택은 J-03(9/29) 때 "1분 데모"를 맞추려고 넣은 것. 당시 노드 전체는 순차 7~9분이었다. 지금은 병렬 4(R-10)로 노드 전체 **135~164초**(README §6, 9/29·10/8 실측 7노드) — 기다릴 만한 시간이 됐다 |
| 다 필요하면 다 있으면 좋다 | **수용.** 기본 = 표준 가이드워드 7종 전부(절차형 3종은 기존 규칙대로 조건부) | 실무 HAZOP 산출물은 전 가이드워드 매트릭스다. 1종만 보여 주면 "판정 셀 누락 0" 이라는 이 앱의 핵심 주장도 화면에서 안 보인다 |
| 노드 순서로 보고 싶다 | **수용(재생).** 공정의 여러 노드를 순서대로 이어 보는 "공정 전체" 보기 | 직접 입력은 노드 1개라 해당 없음. 재생 공정(NH3 4노드 · LPG 충전소 4노드)은 지금 노드 버튼으로 하나씩만 본다 |
| 이탈별로 보고 싶다 | **수용.** "가이드워드별" 묶음 보기 + "파라미터별" 묶음 보기 | HAZOP 의 이탈 = 가이드워드 × 파라미터. 사용자가 말한 "이탈별"은 둘 중 어느 축으로 묶을지 고를 수 있으면 된다 |
| (덧붙임) 화면 문구 "이탈" | **고친다.** 선택칸 질문이 "어떤 이탈부터"인데 실제로 고르는 것은 가이드워드였다 — 용어 혼동의 원인 | `apps/web/app.py:261` |

## 4. 기능 요구사항

### X-1 전체 가이드워드 기본 생성 · P0

1. 직접 입력의 기본 실행을 `run_live`(노드 전체)로 바꾼다. `run_quick` 은 **보조 실행 "가이드워드 하나만 빠르게"**로 화면에 남긴다(X-1b).
   - `HAZOP_LIVE_SCOPE` 는 의미를 정리한다: 기본 = 전체 + 보조 빠른 실행 둘 다 노출. 기존 `quick`/`full` 값은 호환만 유지하고 시험 기대값을 같이 고친다.
2. 기본 버튼 문구: "HAZOP 초안 생성 (가이드워드 전체 · 약 2~3분)". 숫자는 X-G7 실측으로 확정.

### X-1b 보조 실행 "가이드워드 하나만 빠르게" · P0

1. 위치: 기본 버튼 아래 접힌 영역(또는 보조 버튼) — 문구 예: "가이드워드 하나만 빠르게 보기 — 특정 이탈 방향만 먼저 확인할 때 (약 1분)". 펼치면 가이드워드 선택칸 + 실행 버튼.
2. 선택칸 질문은 "어떤 가이드워드만 볼까요?"(이탈이 아니라 가이드워드라고 정확히). 선택지 옆 뜻 표시(기존 `GUIDEWORD_MEANING`) 유지.
3. 결과 화면 요약 줄·출처 줄에 "가이드워드 1종(More)만 생성 — 전체 매트릭스 아님"을 표시해 전체 결과와 헷갈리지 않게 한다. 판정 셀 타일은 "10/10 (1종)".
4. **금지어 시험**: 이 보조 실행의 문구(버튼 라벨·안내 캡션·결과 요약 줄 상수)에 "부스"·"관람객" 이 나오지 않는다. 범위는 이 기능 문구만이다 — 별개 기능인 부스 모드(`?booth=1`, 지시문 V)의 기존 문구("부스 모드 · 오늘 남은 n회")는 대상이 아니다. 부스 모드는 칩 문장·큰 글씨·상한만 바꾸고 이 보조 실행의 문구·동작은 그대로다.
3. 상태 상자: 1/3 해석 → 2/3 파라미터 → **3/3 가이드워드 k/n** + 그 아래 부분 표(가이드워드 묶음이 끝날 때마다 갱신, 완료 순서대로 들어오되 표는 축 순서로 정렬). R-11 `on_progress("guideword", {records})` 를 그대로 쓴다 — `core/` 변경 없음.
4. 병렬 수: `parallel_calls` 4 와 7 을 각 1회 실측(같은 입력, 약 $1.7). 7 이 429 없이 더 빠르면 7, 아니면 4 유지. 측정 전에 판정 규칙을 PRD 에 적어 둔다(R-12 처럼 사전 등록).
5. 실패 처리: 노드 전체에서 한 가이드워드 예외는 그 행만 review(R-10 기존 동작) — 화면에 "가이드워드 X 실패 — 나머지 n종은 정상" 을 띄운다.

### X-2 보기 전환 · P0

1. 결과 표 위에 `st.segmented_control`(또는 radio) — `워크시트 순서 | 가이드워드별 | 파라미터별`.
2. 가이드워드별: 가이드워드 축 순서로 묶고 묶음마다 머리줄 "More — 9건 (해당 없음 1셀)". 파라미터별: 열거 순서로 묶는다.
3. 검토 표와의 관계: **검토 편집은 "워크시트 순서" 보기에서만**(편집 상태 키가 행 인덱스라 정렬이 바뀌면 엉뚱한 행에 붙는다 — R-10 에서 이미 겪은 종류의 결함). 다른 보기는 읽기 전용 표 + 검토 결과(채택/기각) 열 표시.
   - 대안: 편집 키를 행 인덱스 대신 `DeviationRecord.id` 로 바꾸면 모든 보기에서 편집 가능 — 비용 대비 효과를 보고 결정(기본안은 위).
4. 다운로드 순서는 언제나 워크시트 순서(xlsx 12열 규칙 R-02).

### X-3 재생: 공정 전체 노드 순서 보기 · P1

1. 노드 버튼 줄 앞에 "전체(노드 순서)" 버튼. 고르면 그 공정의 캡처된 노드 재생을 `presets.json` 노드 순서로 이어 붙인 결과 1개를 만든다(`Result` 합성 — 레코드 id 는 노드 접두사가 달라 충돌 없음).
2. 지표 타일: 합계(레코드·판정 셀·비용). recall 타일은 공정 합계 — NH3 는 **튜닝 N1 과 홀드아웃 N2~N4 를 섞지 않도록** "튜닝 0.875 · 홀드아웃 0.154" 두 값을 따로, LPG 는 외부 대조 0.909.
3. 출처 줄은 노드마다 캡처 시각·프롬프트 버전이 달라 "노드별 출처" 접힘 목록으로.

### X-4 비용·상한·부스 · P0

| 항목 | 지금(1종) | 바꾼 뒤(전체) |

- 상한은 실행 종류와 무관하게 1회로 센다(기존 규칙). 부스(`?booth=1`) 하루 상한은 기본 실행 기준 비용으로 다시 정한다: 예산 $15 이면 약 15~18회(예산 액수는 §7 Q3). 대회 키 한도(본선 PRD Q3)가 오면 그 값으로.

- 수영장 칩의 As well as 자동 선택(V-6): 칩은 입력 문장만 채우고, 기본(전체) 생성 뒤 **가이드워드별 보기에서 As well as 묶음을 펼친 상태**로 연다. 보조 실행 선택칸의 기본값도 As well as 로 맞춘다(두 경로 모두 산 혼입→염소가스 행이 바로 보이게).
