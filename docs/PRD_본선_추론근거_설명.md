# PRD — AI 추론의 판단 근거 보여 주기 (본선, 새 창 진입점)

작성 2026-10-09 밤 · 브랜치 `finals` · 선행 문서 `docs/PRD_본선_추론경계_Kiro연동.md`(Z-1 정보 4단계 · Z-6 '판단 근거' 열 — 미구현), `docs/지시문_Y_근거다변화_신뢰도_공정순서.md`(Y-3 인용 · Y-4 신뢰도)
근거: 10/9 사용자 — "근거 칸을 '관련 법령·MSDS'로 바꾸면 AI 가 뭘 근거로 추론했는지 질문이 나올 것 같다. 이 방법론을 고도화할 PRD"

## 0. 한 줄 판정

**지금 앱이 행마다 보여 주는 판단 근거는 '법령·MSDS 인용' 하나뿐이다. 실행 결과 행의 절반 이상(직접 입력 실측 54/69, 10/9 Y-G5)은 "인용 없음 (AI 추론)"으로만 나오고, 그 추론이 무엇에서 나왔는지는 아무 데도 없다.**
심사위원 질문 "AI 가 무엇을 근거로 판단했나"에 지금 답할 수 있는 것은 "공식 문서가 같은 위험을 다룰 때만 보여 준다"뿐이다.

고칠 방향: **행 단위가 아니라 문장(원인·결과·권고) 단위로 "어디서 왔는지"를 태그로 받고, 코드가 그 태그를 검사할 수 있게 한다.**
태그는 Z-1 정보 4단계를 그대로 쓴다.
- G(입력의 어느 칸)
- S(어느 인용)
- I(어느 **일반 원리**)

I 는 자유 서술이 아니라 **닫힌 목록(고장 메커니즘 사전)** 에서 고르게 해, "AI 추론"을 "이 원리를 적용한 추론"으로 바꾼다.

## 3. 기능 요구사항

### B-1 문장 단위 근거 태그 (P0)

- 판정 스키마의 `causes` · `consequences` · `recommendations` 항목을 문자열에서 객체로 바꾼다: `{text, basis: [{kind, ref}]}`.
  - `kind="G"`: `ref` = 입력 칸 이름과 값(예: `equipment:압축기`, `safeguards:안전밸브`, `P_kPag`).
  - `kind="S"`: `ref` = 이번 호출 발췌 id(Y-3 인용 계약 그대로 — 원문 구절은 `evidence[]`에).
  - `kind="I"`: `ref` = 메커니즘 사전 id(B-2). 사전이 없는 동안(P0)은 `ref` = 원리 이름 짧은 명사구, 검사는 "입력 설비 유형과 맞는 사전 범주인지"만.
- 프롬프트 규칙: **근거를 먼저 고르고 문장을 쓴다**(스키마 속성 순서 `basis` → `text`). 근거를 댈 수 없는 문장은 쓰지 않는다 — Z "덜하는 것이 낫다"와 같은 원칙.
- 내부 저장은 객체, 워크시트 12열·Excel 표준 열은 지금처럼 문자열(`text` 만) — 표준 양식 불변.
- 스위치 `generation.basis_tags: true|false`(끄면 프롬프트·스키마 바이트 불변, Z·Y 와 같은 방식).

### B-2 고장 메커니즘 사전 (P1 — 방법론의 핵심)

`data/kb/mechanisms.json`. I(일반 추론)를 "모델이 알아서"에서 "이 목록의 원리를 적용"으로 바꾼다.

| 필드 | 예 |
|---|---|
| `id` | `rot.deadhead` |
| `node_type` | `rotating`(Z-2 `inference_policy.json` 노드 유형과 같은 id) |
| `guidewords` | `["No", "Less"]` (유량) |
| `mechanism` | "토출 차단 시 체절 운전 → 압력 상승·과열" |
| `typical_causes` / `typical_consequences` | 짧은 명사구 목록 |
| `source` | 출처와 위치, 이용 조건. 없으면 `"공학 일반 — 팀 작성(검토자 ○○)"` |

- 첫 판은 이미 가진 것에서: Z-2 경계표의 "추론 허용" 항목(노드 유형 6종) + F-06 때 모은 공개 HAZOP 예시 3건(`data/kb/hazop_param_examples.json`, 출처·이용 조건 기록됨).
- **누출 금지**: NH3 정답지(홀드아웃 N2~N4)와 LPG 외부 대조(I1~I4, IOCL 2014)는 평가에 쓰므로 사전에 넣지 않는다. 넣으면 recall 이 오르더라도 그건 정답을 본 결과다(F-06 오염 고지와 같은 문제).
- 검색: 판정 호출에 그 노드 유형의 사전 항목만 넣는다(Y-3 발췌처럼 사용자 턴, 시스템 캐시 유지).

### B-3 심각도·빈도 사유 (P0)

- 스키마에 `s_reason` · `f_reason`(각 1문장). 사유 첫머리는 평가기준 등급 라벨 그대로(예: C-C-37 "S4 치명적", "F2 중").
- 코드 검사: 사유 첫머리의 라벨이 매긴 등급의 라벨과 같은지. 다르면 플래그.
- 빈도 사유는 **안전장치 상태를 반드시 언급**: 입력 안전장치(G) 중 무엇을 고려했는지, 모르면 "안전조치 미상"(Q-Z2 a 와 일치). → 빈도 뭉침(P-2)의 원인을 행마다 드러낸다.

### B-4 검증기 확장 (P0)

| 규칙 | 조건 | 표시 |
|---|---|---|
| `basis_missing` | 근거 태그 없는 문장 | 🟠 근거 확인 필요 |
| `basis_bad_input` | G 태그가 가리키는 칸·값이 입력에 없음 | 🟠 |
| `basis_bad_citation` | S 태그가 이번 호출 인용이 아님(Y-3 계약 재사용) | 🔴 |
| `basis_unknown_mechanism` | I 태그 id 가 사전에 없음(B-2 이후) | 🟠 |
| `grade_reason_mismatch` | 사유 라벨 ≠ 등급 | 🟠 |
| (Z-5) `unsupported_entity` | 문장에 입력·인용에 없는 설비·계장·인터록 | 🔴 — 같이 구현하면 검사기 하나로 묶인다 |

신뢰도 단계는 Y-4 를 유지하고 🟠 를 하나 더 둔다: **"근거 확인 필요"** — 내용은 그럴듯하지만 근거 사슬이 끊긴 행.

### B-5 화면·내보내기 (P0·P1)

- 표 '판단 근거' 열(요약): "입력 2 · 원리 3 · 문서 1"(Z-6 대체).
- 행 펼침 "왜 이렇게 판단했나":
  ```
  원인 1  압축기 토출 밸브 오조작                ← 입력: 설비 '압축기'  +  원리: 토출 차단 → 체절 압력 상승 [rot.deadhead]
  결과 1  배관 파열 · 수소 누출 · 화재              ← 원리: 고압 기체 누출 점화 [com.ignition]  +  문서: MSDS 수소 5항 "쉽게 점화함"
  심각도 4  "S4 치명적 — 다수 사망 가능"           빈도 2  "F2 중 — 입력 안전장치(안전밸브·고압 경보)를 고려"
  ```
- 안내 탭 ④에 "판단 근거 읽는 법" 한 줄 + 4단계 표(이미 있음)와 연결.
- Excel '판단 근거' 시트(B-G7). 워크시트 12열은 그대로.

## 4. 방법론으로서의 주장과 한계 (발표용 정리)

- **주장할 수 있는 것**: "AI 의 모든 문장은 ① 사용자가 준 정보 ② 공식 문서 원문 ③ 출처가 적힌 고장 원리 목록 중 하나 이상에 연결되고, 그 연결은 코드가 검사한다. 연결이 끊긴 문장은 표시된다."
- **주장할 수 없는 것**: 모델 내부에서 실제로 그 근거 때문에 그 문장이 나왔다는 것(설명의 '충실성'). 태그는 사후 합리화일 수 있다. 완화책은 근거를 먼저 고르게 하는 출력 순서와 검사뿐이고, 이것으로 충실성이 증명되지는 않는다. **발표에서 이 한계를 먼저 말한다.**
- 검사를 통과했다고 내용이 맞는 것은 아니다(Y-4 와 같은 고지). 정답 여부는 전문가 표본(B-G6)으로만 말한다.

**지금(구현 전) 질문을 받으면 할 답** — 구현 전이라도 사실대로:
> "지금은 공식 문서가 같은 위험을 다룰 때 그 원문을 붙이고, 입력에 없는 규격 번호·수치는 검증기가 잡습니다. 그 밖의 행은 AI 의 일반 공학 추론이며, 모르는 사업장 정보가 필요한 칸은 지어내지 않고 '정보 부족'으로 남깁니다. 문장마다 근거를 연결해 검사하는 단계를 다음으로 진행 중입니다."

## 5. 비목표 · 리스크

- 비목표: 모델 로그확률·자기평가로 확신도를 매기지 않는다. 사슬형 사고 과정(chain-of-thought) 원문을 화면에 그대로 노출하지 않는다 — 검사할 수 없는 글이 늘 뿐이다.

| # | 리스크 | 대응 |
|---|---|---|
| R1 | 출력 토큰 증가 → 비용·지연(현재 직접 입력 $0.78~1.09 · 95~104 초) | 사전 등록 상한: 비용 +40%, 지연 ≤ 160 초. 넘으면 문장 단위 대신 행 단위 태그로 축소 |
| R2 | 스키마가 깊어져 형식 위반·재시도 증가 | 판정 셀 n/n 유지가 채택 조건. 위반 증가 시 `basis` 를 문자열 배열로 단순화 |
| R3 | 메커니즘 사전의 출처·이용 조건 | 이용 조건 확인된 공개 자료 + 팀 작성(작성자 표기). KOSHA 지침은 공공누리 없음(Y-3 결정)이라 원문 인용 불가 — 개념만 팀이 재서술 |
| R4 | 사전이 정답을 새는 통로가 된다 | §B-2 누출 금지 목록 + 사전과 정답지 낱말 정확 일치 검사(F-06 방식) |
| R5 | 일정 — 발표 10/19 | P0(B-1·B-3·B-4·B-5 요약 열) 10/14 동결, P1 10/16. 못 맞추면 B-2 사전은 발표에서 '설계'로만 |
