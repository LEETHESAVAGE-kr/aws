## K-1 · `.kiro/steering/domain.md` §4 를 실제 `평가기준` 시트로 교체 (우선순위: 상)

**문제**: `domain.md` §4 의 S/F 등급표가 골드셋 원본 `평가기준` 시트와 다르다.
CLAUDE.md 도메인 요약은 "S·F 등급 정의는 골드셋 `평가기준` 시트를 그대로 사용"이라고 지시하므로
steering 쪽이 틀렸다.

**출처**: `data/raw/D1_HAZOP_워크시트.xlsx` 시트 `평가기준` 18행 (파생본: `data/gold/rating_scale.json`)

**조치**: `domain.md` §4 전체(4.1·4.2)를 아래로 교체하고, 위험도 구간표를 새로 추가한다.

```markdown
## 4. S/F 등급 정의 (평가기준 시트 기준)

### 4.1 심각도(Severity, S) 등급

| 등급 | 기준 |
|------|------|
| 1 | 아차사고 — 부상 없음 |
| 2 | 경상 — 응급처치 수준 |
| 3 | 중상·입원 — 영향 선내 국한 |
| 4 | 사망 1인 또는 다수 중상 — 선외 영향 경미 |
| 5 | 다수 사망 또는 항만·인접선 영향(대량 독성 확산) |

### 4.2 빈도(Frequency, F) 등급

| 등급 | 기준 |
|------|------|
| 1 | 매우 희박 — 업계 전체에서도 드묾 |
| 2 | 희박 — 유사 설비 수명 중 1회 미만 |
| 3 | 가능 — 설비 수명 중 1회 정도 |
| 4 | 빈발 가능 — 수년 내 1회 |
| 5 | 빈번 — 연 1회 이상 |

### 4.3 위험도 구간 판정

| 위험도(S×F) | 판정 | 조치 |
|---|---|---|
| 15~25 | 높음 | 허용 불가 — 즉시 개선 |
| 8~14 | 중간(ALARP) | 정량평가(QRA) 대상 — 본 과업의 S1~S3 선정 풀 |
| 1~7 | 낮음 | 절차·점검으로 관리 |

주: 스크리닝용 정성 등급이다. 정량 빈도·확률은 Phase 2 FTA·ETA에서 문헌치로 산정하며
스크리닝 F등급과 혼용하지 않는다.

위험도 = S × F. xlsx 위험도 셀은 수식 `=H*I` 로 유지하고 하드코딩하지 않는다.
기계 판독용 정본은 `data/gold/rating_scale.json` 이다.
```

**주의**: 기존 §4 의 영문 등급명(Negligible/Minor/Moderate/Major/Catastrophic, Rare/Unlikely/…)과
정량 확률 범위(10⁻⁵/년 등)는 원본 시트에 없는 값이므로 **되살리지 않는다.**

## K-2 · `gold-dataset/requirements.md` REQ-06 — 다중값 분해가 실데이터에서 무효 (우선순위: 상, 결정 필요)

**문제**: REQ-06 의 구분자 우선순위는 ①줄바꿈 ②번호패턴 ③세미콜론인데, 원본 워크시트는
셋 중 어느 것도 쓰지 않고 `·` 와 `,` 로 항목을 잇는다. 결과적으로 골드셋 34 레코드의
`causes`·`consequences`·`safeguards_before`·`recommendations` 가 **전부 1원소 배열**이다.
(실측: `data/gold/hazop_nh3.json`, 34/34 레코드가 길이 1)

**`·` 를 구분자로 추가하면 안 된다** — 같은 기호가 한 항목 안에서도 쓰인다:
- 분리해야 함: `"펌프 기동 실패·토출밸브 미개방"` (원인 2건)
- 분리하면 안 됨: `"데드헤드 과압 → 씰·개스킷 응력"` (결과 1건, `씰·개스킷`은 한 덩어리)

**선택지 (하나 고를 것)**

| 안 | 내용 | 비용 | 위험 |
|---|---|---|---|
| **C (권장)** | REQ-06 현행 유지. 대신 evaluation-harness spec 에 "recall 은 **이탈 단위**로 측정하고 원인·결과 리스트는 항목 단위로 비교하지 않는다"를 명시 | 없음 | 항목 수준 평가 불가(예선 범위 밖) |
| B | REQ-06 에 필드별 구분자 정책 추가: `causes`·`safeguards_before`·`recommendations` 만 `·`·`,` 분해, `consequences` 는 제외 | 스펙 1절 + 코드 소폭 | 오분해 잔존, 필드별 예외가 늘어남 |
| A | 원본 xlsx 셀을 줄바꿈 구분으로 수정 후 재빌드 | 34행 수작업 | **출품작 원본을 변형** — `data/README.md` 의 출처 진술과 충돌. 비권장 |

**C 선택 시 조치**: `gold-dataset/requirements.md` REQ-06 끝에 아래 한 문단만 추가한다.

```markdown
**적용 결과 (2026-09-06 실측)**: 원본 워크시트가 `·`·`,` 를 항목 연결자로 쓰므로
이 규칙으로는 34 레코드 전부 1원소 배열이 된다. `·` 는 한 항목 내부에서도 쓰이므로
(`씰·개스킷 응력`) 구분자로 추가하지 않는다. 따라서 원인·결과 리스트는 항목 단위 평가에
쓰지 않으며, FR-08 recall 은 이탈 단위로 측정한다.
```

## K-3 · `bedrock-client/requirements.md` REQ-09 — 미등록 모델 처리·가격표 위치 (우선순위: 중)

**문제 1**: REQ-09 AC 는 미등록 모델 ID 에 `UnknownModelError` raise 를 요구하지만,
CLAUDE.md 범위 규율은 "예외를 던지지 말고 비용 0 + WARNING 로그"를 지시한다(모델 ID 가 대회 계정
확인 후 바뀔 예정이라 예외가 파이프라인을 죽이면 안 되기 때문). 구현은 CLAUDE.md 를 따랐다.

**문제 2**: REQ-09/design §10 은 가격표를 `cost.py` 상수로 두지만, 구현은 `config/prices.yaml`
로 분리했다(지시문 B). 모델 교체 시 코드 수정이 없어야 한다는 steering `aws.md` §2 와도 일치.

**조치**: REQ-09 의 수용 기준을 아래로 교체한다.

```markdown
**수용 기준 (AC-09)**
- `calculate_cost("<가격표 등록 모델 ID>", 1000, 500)` == `0.003 * 1 + 0.015 * 0.5` = `0.0105`.
- 가격표에 없는 모델 ID 는 **예외를 던지지 않고 비용 0.0 을 반환하며 WARNING 을 1회 로깅한다**
  (CLAUDE.md 범위 규율 — 대회 계정 확정 전까지 모델 ID 가 바뀐다).
- `cache_read_tokens > 0` 이면 비용 절감이 반영된다.
- 가격표는 `config/prices.yaml` 에 두고 코드에서 하드코딩하지 않는다.
```

design.md §10 의 `PRICE_TABLE` 상수 블록도 `config/prices.yaml` 로드로 바꾼다.
