## 4. 기능 요구사항

> 리포 규칙(`CLAUDE.md`): **spec 에 없는 기능은 만들지 않는다.** 아래 F-01·F-04 는 기존 spec(`bedrock-client` REQ-12, FR-10) 범위이고, F-02·F-05·F-06 은 Kiro 에서 requirements 를 먼저 추가해야 한다(본선 KIRO 구독 재제공 예정).

### F-01 Bedrock 게이트웨이 전환 · P0 · spec `bedrock-client` REQ-12

1. 키 수령 즉시 **형식 탐침** 1회: Anthropic Messages 형식이면 `ANTHROPIC_BASE_URL`·`ANTHROPIC_API_KEY` 환경변수만으로 기존 `anthropic_client.py` 가 동작한다(SDK 가 환경변수를 읽는다). OpenAI 형식이면 `core/llm/` 에 얇은 어댑터를 추가하고 `structured_output` tool 강제를 그 형식의 function calling 으로 옮긴다.
2. `config/models.yaml` 에 공급자를 하나 더 둔다(`provider: gateway` 등). **`anthropic` 경로는 지우지 않는다** — 한 줄로 되돌릴 수 있어야 한다.
3. `config/prices.yaml` 에 `bedrock-claude-opus-4-8`·`bedrock-haiku`·`bedrock-claude-sonnet-5` 키를 추가한다. 빠지면 비용이 조용히 $0 으로 기록된다(haiku 별칭 때 한 번 겪음).
4. temperature 등 sampling 파라미터는 지금처럼 싣지 않는다 — 최신 모델에서 400.
5. 화면 출처 줄·README §4 를 "Amazon Bedrock 경유(대회 제공 게이트웨이)"로 바꾼다. **운영사가 Bedrock 경유임을 확인해 준 뒤에만.** 확인 전에는 "대회 제공 API" 로만 쓴다.
6. 수용 기준: 직접 입력 실호출 3회 성공(지연·비용·건수가 9/29 범위 ±30% 안), `@pytest.mark.live` 1건 추가, 오프라인 시험 전부 통과.

### F-02 점진 표시 · P0 · FR-10 (requirements 추가 필요)

1. `HazopGenerator.generate()` 에 선택 인자 `on_batch(guideword, records_so_far)` 를 둔다. 병렬 경로는 `pool.map` → `as_completed` 로 바꾸되, **최종 레코드 순서·id 는 지금과 같게** 마지막에 가이드워드 목록 순서로 재조립한다(골든 스냅샷 유지).
2. 비용 합산·`review_guidewords` 는 여전히 메인 스레드에서만 — O-1 의 AST 구조 시험이 계속 통과해야 한다.
3. 화면: 진행 `st.status` 아래에 표 자리를 먼저 만들고 묶음마다 갱신, "가이드워드 4/7 판정 완료" 카운터.
4. 수용 기준: 첫 행 표시 ≤15초(1440×900, 배포), 최종 표가 점진 표시 없이 생성한 것과 행 단위로 동일(mock 시험), 기존 268개 통과.

### F-03 발표 패키지 · P0 · 코드 아님

1. **7분 대본**(초 단위): 0:00 사고 사례 한 장(구미 불산) → 0:40 "워크시트 한 줄이 비어 있었다" → **1:00 실행 버튼(이때 누른다)** → 1:00~4:30 설계(매트릭스 강제·스키마·검증기)·정확도(0.875/0.154 원인 포함)를 설명하는 동안 화면 한쪽에서 행이 늘어난다 → 4:30 결과·xlsx·LOPA → 6:00 Bedrock·비용·한계 → 6:40 마무리.
2. **대체 경로**: 실패하면 실패 상자의 "실측 사례 보기"로 30초 안에 전환, 대본 문장도 준비("방금 같은 입력으로 어제 생성한 결과입니다").
3. **Q&A 탄약 10문**(각 30초 답): Bedrock 경유 여부 · 홀드아웃 15.4% · 노드당 $0.83 · 골드셋 저자 · 할루시네이션 대책(검증기 10/10) · 실무 도입 경로 · 데이터 보안(사내 자료 미사용) · RAG/에이전트 미사용 이유 · F 등급 단조 · 예선 이후 바뀐 것.
4. 리허설 3회 녹화, 화면공유 해상도·글자 크기 확인. 발표 당일 1시간 전 배포 깨우기 + 실호출 1회.

### F-04 부스 모드 · P1 · FR-10

1. URL 쿼리 `?booth=1` 로 켠다(기본 화면 무변경). 큰 글씨, 예시 칩을 **일반 관람객 문장**으로 교체: "학교 실험실 수소 실린더 교체", "아파트 LPG 배관", "수영장 염소 소독 약품 주입" 등.
2. 상한을 부스 예산으로: 예) 하루 60회 × $0.15 ≈ **$9**. Secrets `HAZOP_DAILY_LIMIT` 로 당일만 올린다. 세션 상한은 부스 PC 한 대라 의미가 없으니 부스 모드에서는 쿨다운(직전 생성 진행 중이면 버튼 잠금)으로 대체.
3. 대기 시간 채우기: 생성 중 화면에 "AI 가 지금 검토하는 가이드워드" 카운터 + F-02 점진 표 + 사고 사례 카드 순환.
4. QR(배포 URL) 출력물 — 관람객 폰에서도 열리게. 투표 유도 문구는 운영 규칙 확인 후.
5. **오프라인 대비**: KU WIFI 단절 시 재생 모드만으로 시연할 수 있게 노트북 로컬 실행 + 휴대폰 테더링 2중화.

### F-05 검토 도구 · P1 · backlog P-10 (requirements 추가 필요)

1. 결과 표를 `st.data_editor` 로: 열 추가 `검토`(채택/기각/수정), 원인·결과·권고·S·F 편집 가능.
2. 내보내는 xlsx 에 `검토` 열과 "수정됨" 표시, 기각 행은 별도 시트. LOPA 초안은 채택 행만.
3. 서명·이력·다중 사용자는 **하지 않는다**(비목표).
4. 수용 기준: AppTest 로 행 1개 기각 → xlsx 기각 시트에 1행, 본 시트에서 빠짐.
5. 의미: 9/29 실무자 평가 "검토할 도구가 없다"에 대한 직접 답, 부스에서 만질 거리, 화면 부제("전문가는 검토만")와 기능을 일치시킨다.

### F-06 공개 자료 few-shot/RAG · P2 · 새 spec 필요

1. 자료: `../참고자료/공개_HAZOP_워크시트/`(5건, `출처.md`). 리포에는 **원문을 넣지 않고** 직접 발췌·요약한 예시 행만 `data/kb/` 에 출처·라이선스와 함께(리포 규칙 1·`data/README.md`).
2. 목표는 홀드아웃 실패 원인(설비·절차형 파라미터 미생성)에 대한 시험: 파라미터 도출 프롬프트(`matrix_enumerate.md`)에 공개 자료 예시 2~3개를 넣는다.
3. **누출 금지**: 골드 N2~N4 어휘·문장 사용 금지. ORNL 암모니아 자료는 홀드아웃과 물질이 같으므로 넣으면 포함/미포함 두 값을 함께 공개.
4. 재측정 비용 약 $2.5·반나절. 결과가 나쁘면 넣지 않고 "시도했고 효과 없음"으로 발표에 쓴다.
5. **회사(KECC) 실자료는 마스킹해도 사용하지 않는다** — 리포 불변 규칙 1.
