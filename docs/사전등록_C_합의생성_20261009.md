## 1. 합의 규칙 (구현이 따를 정의)

- **열거 1회 공유**: 파라미터 열거는 1회, 가이드워드 판정만 N회 독립 호출. 동시 호출 상한은 `parallel_calls`(7) 그대로 — 7×3=21 호출은 한꺼번에 나가지 않는다.
- **셀 상태**(실행마다): `해당`(레코드가 되는 완전한 셀) · `해당 없음` · `정보 부족`(Z-3 보류 조건과 같음) · `누락`(호출 실패·셀 미반환·필수 필드 결측으로 버려질 셀).
- **셀 투표**: `누락`을 뺀 표로 다수결. 최다 득표가 둘 이상이면(1:1:1, 또는 두 실행만 남아 1:1) `정보 부족` — 덜하는 쪽(Z 원칙). 모델이 보류를 적지 않았는데 동률로 보류가 되면 없는 정보 칸에 "반복 실행 간 판정이 갈림"을 적는다. 세 실행 모두 `누락`이면 그 셀은 판정하지 않은 셀이다.
- **문장 짝짓기**(해당 셀의 원인·결과·권고, 칸별로): 실행 순서대로 문장을 훑어 기존 묶음 대표 문장과 **e5 코사인 ≥ τ = 0.92** 또는 정규화 문자열 일치면 그 묶음에 넣는다(한 묶음에 같은 실행의 문장은 하나만, 가장 비슷한 묶음 우선). 아니면 새 묶음. `agree = 묶음에 든 실행 수 / N`. 대표 문장은 묶음의 첫 문장.
- **남길 문장**: `agree ≥ 2/3` → 워크시트 칸. `1/3` → '참고' 목록(화면 접힘 + Excel '반복 일치' 시트).
- **심각도·빈도**: 해당 실행들의 값을 정렬해 가운데 값(짝수 개면 위쪽 — 위험을 낮춰 잡지 않는 쪽). 값이 하나라도 다르면 '갈림' 표시(예: "심각도 3·4·4 (갈림)").
- **나머지 칸**: 이탈 서술은 첫 해당 실행의 것. 기존 안전장치·인용은 해당 실행들의 합집합(인용 검사는 각 실행이 받은 발췌의 합집합 기준).
- **스위치**: `generation.consensus_runs: 1|3`. 1 이면 지금 코드 경로 그대로(프롬프트·스키마·레코드 직렬화 바이트 동일). 빠른 보기(가이드워드 1종)는 합의 대상이 아니다.

### τ 를 0.92 로 정한 근거 (PRD 후보 0.85 에서 바꿈)

측정에 쓰지 않는 9/29 재캡처 쌍(N1·P1·P2 각 2회, `data/replay/*_20260929{,b}.json`)에서 같은 (가이드워드, 파라미터) 셀의 원인·결과·권고 문장 쌍 2,768개의 코사인을 쟀다(`multilingual-e5-small`, `query:` 접두).

| 문턱 | 전체 쌍 중 짝으로 잡히는 비율 | 문장별 최근접이 문턱 이상 |
|---|---|---|
| 0.85 | 63.7% | 90.6% |
| 0.90 | 18.8% | 43.3% |
| **0.92** | **10.8%** | **27.6%** |
| 0.94 | 5.5% | 14.2% |

같은 셀 안 문장은 주제가 같아 코사인이 0.82 아래로 거의 내려가지 않는다(10% 분위 0.825). 0.85 면 다른 원인끼리 대부분 한 묶음이 된다. 구간별 표본 40쌍을 읽은 판단(작성자 = 이 세션, 사람 판정 아님): ≥0.95 거의 전부 같은 뜻, 0.92~0.95 대부분 같은 뜻(일부는 같은 주제의 다른 기전), 0.90~0.92 대부분 다른 문장. → 0.92.
**한계**: 판정자가 사람이 아니고 표본이 작다. 0.92 는 "같은 뜻을 놓치는 쪽"으로 기운 값이라 agree 를 낮게 잴 가능성이 높다 — 결과 해석 때 이 방향을 같이 적는다.

## 2. 실행 설계

| 입력 | 기준 | 경로 |
|---|---|---|
| N1 (튜닝) | NH3 골드 기준 | `HazopGenerator.generate`(재생 캡처와 같은 경로) |
| N2 (홀드아웃) | NH3 골드 기준 | 같음 |
| 직접 입력 "아파트 LPG 공급"(`tools/measure_xg7.INPUT`) | C-C-37 | A 는 `service.run_live`(화면과 같은 경로, 입력 해석 포함) |

입력마다 합의 실행 2벌:
- **A** — 실제 경로 그대로 `consensus_runs=3`(열거·해석 포함). 지연·비용(지표 ③④)은 A 로만 잰다.
- **B** — A 와 **같은 파라미터 목록·같은 NodeMeta** 로 `consensus_runs=3`(열거·해석 호출 없음).

열거를 고정하는 이유: 합의는 판정만 반복하고 열거는 1회 공유한다. 열거가 바뀌면 셀 자체가 달라져 "판정 안정성"을 잴 수 없다. **따라서 이 측정은 열거 변동을 포함하지 않는다** — README §6 의 "보류 15셀 → 6셀"(전체 실행 두 번)과 같은 양이 아니다. 열거 변동은 합의로 줄지 않는다(1회 공유)는 사실을 결과에 같이 적는다.

A·B 의 판정 6회(A1~A3, B1~B3)는 모두 같은 파라미터에 대한 독립 판정이다.

## 3. 지표

| # | 지표 | 정의 |
|---|---|---|
| ① 주 | **셀 판정 안정성** | 두 결과 사이에서 셀 상태(해당/해당 없음/정보 부족/누락)가 같은 셀 비율. 분모 = 가이드워드 × 열거 파라미터 전 셀. 셀 키 = (가이드워드, 정규화 파라미터명) |
| | 합의 | **A 합의 vs B 합의** (1쌍) |
| | 단일 기준 | 6회 판정의 모든 쌍(15쌍) 평균. 보조로 A1 vs B1 1쌍 |
| | 보조(합의) | 6회를 3+3 으로 나누는 10가지 분할의 평균(재호출 없음, 같은 투표 규칙) |
| ② | 보류 수 | 합의 A·B 의 정보 부족 셀 수 vs 단일 6회의 범위·평균 |
| ③ | 비용 | A 총비용(해석·열거 포함). 단일 실행 환산 = 열거(+해석) + 판정 1회분 평균 |
| ④ | 지연 | A 벽시계(직접 입력은 화면과 같은 `run_live` 경로). 단일 기준은 10/9 실측(직접 입력 84.6~104초) |
| ⑤ | recall | N1·N2 만, 합의 A·B 와 단일 6회. **내부 보고만 — 화면 비표시**(10/9 사용자 결정) |
| ⑥ | 문장 합의 분포 | 원인·결과·권고별 묶음의 3/3·2/3·1/3 비율, **남는 원인이 0개인 해당 행 수**, 심각도·빈도 '갈림' 행 비율 |
| ⑦ | 형식 | 판정 셀 n/n(합의 결과), 실행별 review 가이드워드, 429·재시도 로그 |

## 4. 비용·지연 예상

- 비용: 입력당 A ≈ 단일 ×2.6~3, B 는 열거 없이 비슷. 단일 $0.78~1.40(10/9 Y-G5·Z 스모크) → 6벌 합계 **약 $14~24**. 사용자 결정("비용 상관없어", 10/9)으로 상한 없이 공개만 한다.
- 지연: 판정 21호출 / 동시 7 → 3물결. 단일 판정 물결이 약 60~80초라 **A 지연은 약 200~260초로 예상**(상한 160초를 넘을 가능성이 높다 — 예상을 미리 적어 둔다).

## 5. 판정 규칙

1. **안정성**: 세 입력을 합친 셀로 ① 합의(A vs B) 일치율 > 단일 15쌍 평균 일치율이면 "안정성 오름". 입력별 값도 그대로 적는다(한 입력이라도 낮아지면 그 사실을 적는다).
2. **지연**: 직접 입력 A ≤ 160초.
3. 갈래:
   - 1·2 모두 충족 → `consensus_runs: 3` 기본 켬.
   - 1 충족·2 미충족 → **기본은 N=1 유지**, 합의는 '정밀 생성'(다운로드용) 별도 실행으로만 제안(Q-C3 갈래). 켜는 결정은 사용자.
   - 1 미충족 → 합의 기능은 꺼 둔다(`consensus_runs: 1`), 결과를 README 에 그대로.
4. ⑥에서 남는 원인 0개 행이 해당 행의 20%를 넘으면, 채택 여부와 무관하게 "워크시트 원인 칸이 비는 행"을 결과에 명시하고 화면 처리(참고 문장을 같이 보이기 등)는 사용자 결정으로 올린다. 이 문턱(20%)도 사전 등록이다.
5. recall(⑤)은 판정에 쓰지 않는다 — 보고만.
