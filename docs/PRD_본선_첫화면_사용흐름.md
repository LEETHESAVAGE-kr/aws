## 0. 한 줄 판정

**첫 화면이 "무엇을 하는 서비스인지"보다 "문장 한 문단"이라는 입력 방식 하나를 먼저 말한다.** 그런데 실제 화면에는 입력 방식이 둘(문장·선택)이고, 결과를 보는 길도 둘(새로 생성·실측 사례)이다.
1·2·3 단계 카드가 이 갈림길을 보여 주지 않아, 사용자가 카드에서 읽은 흐름과 오른쪽 작업 카드에서 하는 일이 어긋난다.
고칠 방향은 셋이다.
① 제목은 **서비스 이름(명사)**, 그 아래에 하는 일을 친절하게 적는다.
② 큰 흐름(갈림길 포함)을 첫 화면에서 한 번에 보여 준다.
③ 입력 카드 안의 순서를 **입력 방식 → 공정 예시 → 입력 → 생성**으로 바꾼다.

## 1. 피드백 원문

> 1. 어떤 공정을 분석할까요? 부분에 순서 변경 필요: UX 관점에서 흐름에 맞게. e.g. 입력 방식(문장으로 쓰기, 골라서 입력)이 먼저 나오고, 이후 문장 쓰기를 선택했다면 "수소 충전소, 메탄올 하역, 실란 가스 캐비닛"과 같은 공정을 선택하여 예시 문장이 나올 수 있게.
> 2. 골라서 입력이라는 워딩 변경 필요.
> 3. 사용자가 해당 서비스에서 가장 첫 번째로 보는 페이지로 직관적으로 해당 서비스가 이해되어야 함. 제목은 명사형으로 서비스의 명칭이 나오고, 그 아래 해당 서비스가 하는 일이 친절하게 설명. 이후 1,2,3번으로 나오는 유저 플로우를 실제 사용자 관점에서 A-Z까지 생각했을 때, 이해가 안 되는 부분이 없도록. 예를 들어 현재는 1번에 공정을 문장으로 설명이라고 되어 있지만, 실제로는 문장 설명과 골라서 입력 중에 고를 수 있고 골랐을 때 인터랙션들이 다 달라짐. 큰 틀의 주요 UX 플로우를 정리하면서 전체적 서비스 사용 흐름을 알려주기. 각 세부 흐름은 각 세부 서비스 파트에서 사용 방법 흐름에 맞춰서 설명.

## 3. 목표 흐름 — 큰 틀(첫 화면에서 보여 줄 것)

```
① 공정 정보 넣기 ─┬─ 문장으로 설명하기 : 공정 예시를 고르면 예시 문장이 채워짐 → 고쳐 쓰기
                   ├─ 항목 선택해 입력하기 : 공정 예시를 고르면 칸이 채워짐 → 물질·설비·압력·안전장치 고르기
                   └─ (기다리기 싫으면) 완성된 사례 보기 : 공정 → 노드 고르기 → 바로 ③
② AI 가 HAZOP 표 만들기 (약 1.5–2분) : 점검 항목 → 이탈마다 원인·결과·심각도·빈도·권고 → 근거 인용·모르는 정보는 '정보 부족'으로 남김
③ 검토하고 내려받기 : 표 읽기(펼쳐 보기) → 채택·기각·수정(편집 표) → Excel · LOPA Word · 신뢰도 JSON
```

세부 사용법은 그 기능이 있는 자리에서 한두 줄로 적는다(피드백 3 끝 문단). 첫 화면에는 위 세 줄만.

## 4. 요구사항

### U-1 첫 화면 제목·설명 (P0)

| 항목 | 지금 | 바꿀 것(초안 — Q-U1 결정) |
|---|---|---|
| 작은 머리말 | AI 위험성평가 코파일럿 | 고려대 × AWS AI Innovators 2026 (또는 삭제) |
| 제목(명사형, 서비스 이름) | 공정을 한 문단으로 쓰면, … 나옵니다. | **HAZOP 코파일럿** — 부제목 한 줄: "AI 위험성평가 초안 도우미" |
| 설명(친절하게, 2~3문장) | 며칠짜리 HAZOP 회의의 … | "화학공장·가스설비의 공정 정보를 넣으면, AI 가 '설비가 원래 하려던 일에서 벗어나면 무슨 일이 생기나'를 빠짐없이 따져 HAZOP(위험과 운전 분석) 표 초안을 만듭니다. 근거가 있는 내용은 법령·MSDS 원문을 함께 보여 주고, 모르는 정보는 지어내지 않고 '정보 부족'으로 남깁니다. 최종 판단은 전문가가 합니다." |

수용 기준: 제목이 명사형 서비스 이름이다 · 설명에 'HAZOP'의 풀이가 있다 · 전문 용어(가이드워드·셀·노드·LOPA)는 설명에 쓰지 않는다.

### U-2 큰 흐름 카드 (P0)

- 1·2·3 카드를 §3 의 세 단계로 바꾼다. **1번 카드 안에 갈림길 세 가지**(문장 / 항목 선택 / 완성된 사례)를 한 줄씩 보여 준다.
- 각 카드에 걸리는 시간·결과물을 숫자로: ② "약 1.5–2분", ③ "Excel 6시트 · Word · JSON".
- 신뢰 칩에 10/9 기능 2개 추가: "법령·MSDS 근거 인용", "모르는 정보는 '정보 부족'으로".

수용 기준: 카드만 읽고 세 갈림길을 모두 말할 수 있다(사람 시험 1명 — 팀원).

### U-3 입력 카드 순서 (P0, 피드백 1)

```
[새로 만들기 | 완성된 사례 보기]            ← 모드(문구 Q-U3)
어떤 공정을 분석할까요?
입력 방식  (●) 문장으로 설명  ( ) 항목 선택   ← 맨 먼저
공정 예시  [수소충전소] [메탄올 하역] [실란 가스 캐비닛]
           └ 문장 방식이면 "예시 문장이 칸에 채워집니다", 항목 방식이면 "예시 값이 칸에 채워집니다"
입력       문장 칸  |  항목 양식
[HAZOP 초안 생성]
```

- 예시 칩은 **고른 입력 방식만** 채운다(지금은 둘 다 채운다). 방식을 바꾸면 다른 쪽은 빈 칸 — 단, 이미 쓴 내용은 지우지 않는다.
- 예시 칩 아래 한 줄 안내가 방식에 따라 바뀐다.
- 부스 모드(`?booth=1`)의 칩도 같은 순서.

수용 기준: AppTest — 입력 방식 위젯이 예시 칩보다 위 · 문장 방식에서 칩 → 문장 칸만 채워짐 · 항목 방식에서 칩 → 양식만 채워짐.

### U-4 '골라서 입력' 문구 (P0, 피드백 2) — Q-U2 결정

후보: **항목 선택해 입력** / 양식으로 입력 / 항목별 입력 / 체크해서 입력. 추천: **"항목 선택"**(짝: "문장으로 설명").
같은 말을 첫 화면 카드·입력 방식·안내 탭·README 에 똑같이 쓴다.

### U-5 항목 양식 안내 (P1)

- 필수 칸 표시: 물질·설비 옆 `필수`. 나머지는 "모르면 비워 두세요 — 비우면 '정보 부족'으로 다룹니다".
- 설비 칸 안내: "흐름 순서대로 — 받는 곳에서 내보내는 곳으로".
- 안전장치: "설정값이 있으면 직접 입력(예: 고압 경보(설정 95 MPa))" 유지, '안전장치 없음' 체크 설명을 한 줄로 줄인다.

### U-6 진행 표시 정합 (P1)

- 항목 선택 경로는 해석 단계가 없는데 지금 첫 줄이 "✅ 1/3 JSON 입력 — 해석 생략"이다(`service.progress_text` 의 `parsed_by == "json"` 분기). → "✅ 1/3 입력한 항목 확인 — 수소 · 기체 · 설비 4개"처럼 입력 요약으로 바꾼다. 'AI 가 한 일' 탭의 "사용자가 준 것 (JSON)"도 "(항목 선택)"으로.

### U-7 결과 화면 읽는 순서 (P1)

- 결과 맨 위에 한 줄: "① 표를 읽고 → ② 🔴·⚪ 행을 먼저 확인하고 → ③ 편집 표에서 채택·기각 → ④ 내려받기".
- 배지(평가기준·안전조치 미반영·참고용)는 한 상자 안에 모은다.

### U-8 'HAZOP 이 처음이라면' 앞에 '이렇게 쓰세요' (P2)

- 방법론 탭 앞에 앱 사용법 탭 1개: 세 갈림길별 30초 따라하기(스크린샷 없이 글 3줄씩).

## 5. 비목표

- 기능 추가 없음 — 화면 순서·문구·안내만 바꾼다. 생성 로직·프롬프트·내보내기는 건드리지 않는다.
