# 실무자 관점 평가 — HAZOP 코파일럿 (2026-09-29)

> **평가자·근거의 한계를 먼저 적는다.** 이 문서는 Claude Code 가 공정안전 실무자(HAZOP 리더·검토자)의 눈으로
> 산출물을 읽고 쓴 것이다. 자격 있는 HAZOP 리더의 검토가 아니다. 근거는 커밋된 재생 파일 4개
> (`data/replay/{n1,n4,p1,p2}_20260929.json`, 레코드 291건)의 **전수 통계**와 표본 레코드 판독이며, 모두 **n=1 실행**이다.
> 염소·LPG 공정의 일반 위험(예: 기화기 NCl3 축적)은 **내 일반 지식에서 온 것이고 문헌을 대조하지 않았다** — 해당 문장에 표시했다.

## 한 줄 결론

**브레인스토밍 초안으로는 쓸 만하고, 검토회의 사전자료로는 손이 많이 가며, 제출용 워크시트로는 아직 안 된다.**
이탈·원인·결과 서술의 질은 예상보다 높다. 그러나 실무자가 워크시트에서 가장 먼저 보는 두 칸 —
**기존 안전장치**와 **빈도(F)** — 가 구조적으로 비어 있거나 한 값으로 뭉쳐 있어, 위험도 순위와 권고의 타당성을 판단할 수 없다.

## 잘 된 점 (근거 포함)

1. **셀 판정 누락 0.** 4파일 모두 `judged/expected` 가 100%(77/77·100/100·84/84·77/77). 사람이 매트릭스를 칠할 때 흔히 생기는
   "빈 칸 건너뛰기"가 없다.
2. **물질 특성을 아는 서술.** P2(염소) `Other than/조성` 은 "건조 염소에 수분 혼입 → 강한 부식 → 관통 누출", 권고로
   "정비 후 건조 질소 퍼지·수분 확인 의무화"를 냈다. `Reverse/유량` 은 "기화기 하류 압력 > 컨테이너 헤드압 → 역류", 권고
   "체크밸브 + 정기 작동시험 + 차압 감시". 실무자가 쓰는 문장과 거의 같다. P2 전체에서 "수분" 28회·"부식" 63회.
3. **권고가 구체적이고 중복이 적다.** 4파일 권고 736건 중 완전 중복 1건. "경보 설치" 같은 뭉뚱그린 권고보다
   "펌프 최소유량 순환라인 또는 저유량 보호 트립" 수준.
4. **지어낸 규격·수치 0.** verifier 기준 280건(N1~N4) 플래그 0 — 모델이 KOSHA·API 번호를 만들어 넣지 않는다.

## 실무 투입을 막는 문제 (심각도 순)

### P-1 · 기존 안전장치(Before) 열이 비어 있다 — **구조 결함**

| 파일 | 입력 safeguards | `safeguards_before` 가 채워진 레코드 |
|---|---|---|
| N1 (NH3) | 없음 | 0/61 (정상 — 입력이 비었음) |
| N4 (NH3) | 없음 | 0/97 (정상) |
| **P2 (염소)** | 누출감지기·긴급차단밸브·스크러버 **3개 제공** | **0/64** |
| P1 (LPG) | 안전밸브·ESV·누출감지기 **3개 제공** | 58항목(고유 4개). **"안전밸브" 0회**, "gas detector"(영문) 1회 |

- **원인(코드 확인)**: 판정 프롬프트 `core/agent/prompts/deviation_generate.md` 시스템 지시는 "`safeguards_before` 는
  **노드 메타에 주어진 기존 안전장치 중에서만** 고른다"인데, 사용자 턴 템플릿(`## 노드 {node} · {substance} · {equipment}`)과
  `generate.py::_generate_batch` 의 `_fill` 에 **safeguards 가 없다.** P·T·상도 없다. 모델은 안전장치를 받은 적이 없으니
  규칙대로 비우거나(P2), 열거 단계 근거문에 섞여 온 단서로 일부만 추측한다(P1).
- **실무 영향**: P1 `More/압력`(S5·F3)은 기존 안전장치가 `[]` 인데 권고 1순위가 "안전밸브 용량 적정성 재검토"다 —
  안전밸브가 있다는 걸 알면서 Before 칸은 비었다. 실무 워크시트의 핵심 논리("기존 방호가 충분한가 → 부족분만 권고")가 성립하지 않는다.
  위험도도 방호 전후 구분 없이 매겨진다.

### P-2 · 빈도(F)가 한 값으로 뭉친다 — 위험도 순위를 못 쓴다

| 파일 | F=3 비율 | S 분포 | 위험도 ≥15 |
|---|---|---|---|
| N1 | 52/61 (85%) | S4 30·S3 19·S5 11 | 11 |
| N4 | 92/97 (95%) | S4 57·S3 32 | 7 |
| P1 | 60/69 (87%) | S4 30·S3 24·S5 10 | 9 |
| P2 | 54/64 (84%) | S4 43 | 9 |

- F 정의 "3 = 설비 수명 중 1회 정도"가 기본값처럼 쓰인다. F=1 은 291건 중 **0건**. 위험도 = S×F 이므로 순위는 사실상 S 순위다.
- **실무 영향**: 5×5 매트릭스에서 대부분이 12(4×3) 한 칸에 몰린다. 검토회의가 "어디부터 볼까"를 이 표로 정할 수 없다.
  (원인 추정: 판정 단계가 기존 안전장치·운전 빈도 정보를 받지 못해(P-1) 빈도를 가를 근거가 없다. 미검증.)

### P-3 · 평가기준(S·F 정의)이 NH3 **선박** 전용인데 모든 공정에 쓴다

- `data/gold/rating_scale.json` 의 S 정의: "3 = 영향 **선내** 국한", "5 = **항만·인접선** 영향(대량 독성 확산)".
- LPG 출하장·염소 하역장(육상)에 이 문구로 S 를 매기면 기준이 맞지 않는다. 실무자는 회사·사업장 위험성 매트릭스를 쓴다.
- **실무 영향**: 예시 공정 2개의 S·F 는 "선박 기준을 육상에 빌려 쓴 값"이다. 화면에 이 사실이 표시되지 않는다.

### P-4 · 출하·하역 같은 **작업 절차**에 절차형 가이드워드가 붙지 않는다

- `PROCEDURAL_KEYWORDS = {절차, 운전, 조작, 순서, 작업, procedure, operation}` 가 **설비명**에 있을 때만 Too early·Too late·Wrong action 을 쓴다.
- P1 "출하", P2 "하역·기화"는 사고의 상당 부분이 **로딩암 연결·분리, 컨테이너 교체, 밸브 순서** 같은 작업에서 나는 공정인데
  둘 다 표준 7종만 받았다. (N4 는 설비명이 "이송 운전 절차"라 붙었다.)
- **실무 영향**: "밸브를 열기 전에 로딩암 연결 확인 누락", "컨테이너 교체 중 잔압 미해소" 같은 절차 이탈이 체계적으로 빠진다.
  (일부는 표준 가이드워드 안에 섞여 나오지만 — P1 "로딩암 연결·분리" 파라미터 — 시점·순서 이탈로 판정되지 않는다.)

### P-5 · 노드가 너무 크다

- P1 은 저장탱크 → 출하 펌프 → 로딩암을 **한 노드**로 본다. 실무에서는 최소 2~3노드(탱크 / 펌프·배관 / 로딩암·탱크로리)로 나눈다.
- 결과: `More/압력` 한 행에 "외기·화재로 탱크 증기압 상승"과 "펌프 데드헤드"가 원인으로 섞인다. 원인마다 방호계층이 달라 LOPA 로 넘길 수 없다.
- 도구가 노드 분할을 돕지 않는다(입력 1개 = 노드 1개).

### P-6 · 설계조건 오독

- P2 입력 `T_degC: 20`(컨테이너·공급 조건)을 `More/온도` 에서 "**기화기** 온도가 20°C 설계값을 크게 초과"로 썼다. 기화기는 원래 가열 설비다.
- 원인(추정): P·T 는 판정 단계에 직접 가지 않고 열거 단계 근거문을 거쳐 간접 전달된다(P-1 과 같은 템플릿 문제). 어느 설비의 조건인지가 사라진다.

### P-7 · 12열 워크시트 중 2열이 항상 비어 있다

- `시나리오 연계` 291/291 공란, `evidence`(근거) 291/291 공란. xlsx 의 근거 시트도 비어 있다.
- **실무 영향**: 제출용 워크시트는 고위험 행을 LOPA 시나리오 번호로 잇는다. 지금은 사람이 전부 수작업으로 이어야 한다.
  README 는 이를 한계로 공개하고 있다(본선 과제) — 숨긴 문제는 아니다.

### P-8 · 물질 특유 위험이 빠질 수 있다 (예시 1건, 체계적 결론 아님)

- 염소 기화기의 **삼염화질소(NCl3) 축적·폭발**은 염소 기화 설비의 대표 위험으로 알려져 있다(**내 일반 지식 — 문헌 미대조**).
  P2 64건에 NCl3·삼염화질소 언급 0회. "염소-금속 고온 반응"은 1회 나오지만 기화기 과열과 묶이지 않았다.
- n=1 이라 "모델이 모른다"가 아니라 "이번 실행에서 안 나왔다"다. 전문가 골드셋이 없는 공정이라 누락률을 잴 수도 없다.

### P-9 · 용어가 흔들린다

- 같은 안전장치가 `ESV` 24회 · `ESV(긴급차단밸브)` 7회 · 입력 원문 `긴급차단밸브(ESV)` 0회. `가스누출감지기` 26회와 `gas detector` 1회.
- 실무 워크시트는 P&ID 태그·설비 대장 명칭과 1:1 이어야 한다. 표기가 흔들리면 필터·집계가 깨진다.
