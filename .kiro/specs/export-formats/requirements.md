# 작성 방식: 손 작성(PRD §6 "크레딧 소진 시 .kiro/ 구조는 손으로 유지" 경로). Kiro 크레딧 미사용.

## 범위

`core/export/` 아래 파일과 `tests/test_export.py`(+ 스냅샷 기대값 `tests/golden/`).
신규 클래스 ≤ 3개, 태스크 ≤ 6개(지시문 D 상한).

이 spec 은 **LLM 을 호출하지 않는다.** `core/llm` 은 물론 `core/agent` 도 임포트하지 않는다
(`core/agent/generate.py` 가 모듈 최상위에서 `core/llm` → `boto3` 를 끌어오기 때문에,
`core/export` 가 `core/agent` 를 임포트하면 자격증명 없는 환경에서 boto3 의존이 생긴다).
입력은 덕 타이핑으로 받는다(R-01).

이 spec 이 **포함하지 않는 것**: 근거 검색·인용 생성(FR-04), 신뢰도 판정(FR-06 — 이 spec 은
표시만 한다), recall·지표 계산(FR-08), API 응답·다운로드(FR-09), UI(FR-10),
`data/raw/` 원본 수정(CLAUDE.md 불변규칙 2).

## 요구사항 (EARS 형식)

### R-01 입력 정규화

**The system shall** 다음 두 형태의 입력을 같은 함수로 받는다:
(a) `DeviationRecord` 인스턴스 목록(`model_dump()` 를 가진 객체), (b) 같은 필드의 `dict` 목록
(골드셋 JSON 그대로).

- 골드셋에는 `evidence`·`confidence` 가 없다. 기본값은 `evidence=[]`, **`confidence=None`**
  (미부여). `"inferred"` 로 채우지 않는다 — 사람이 작성한 골드 레코드를 "모델 추론"으로
  표시하면 신뢰도 시트가 거짓이 된다(NFR-03).
- `No` 열은 입력 순서 1부터의 연번이다. `id` 는 워크시트에 쓰지 않는다(원본 양식에 없다).
- 노드 열 조립 규칙: `equipment` 가 1개면 `"{node} {equipment[0]}"`(원본과 동일). 0개면
  `"{node}"` 만. 2개 이상이면 `"{node} " + "·".join(equipment)` (리스트 열과 같은 연결자).
  실측 골드셋 34건은 전부 1개다.
- 가이드워드 열: `"{guideword} ({parameter})"`.
- 리스트 필드(원인·결과·기존 안전장치·권고)는 `"·"` 로 잇는다. 빈 리스트는 빈 문자열.

**수용 기준**: 골드셋 34건(dict)과 `DeviationRecord` 로 만든 레코드가 같은 정규화 함수를
통과하며, 골드셋 1번 레코드의 노드·가이드워드 열이 원본 2행(`"N1 벙커링선 매니폴드"`,
`"No (유량)"`)과 문자열 일치한다.

### R-02 xlsx `HAZOP워크시트` 시트

**The system shall** 실측 12열을 **같은 순서·같은 헤더 문자열**로 쓴다.

- 위험도(J) 는 값이 아니라 **수식** `=H{row}*I{row}`. `risk_score` 값을 셀에 넣지 않는다.
- 열 너비를 실측표대로 설정한다. I 열은 설정하지 않는다(원본 미지정).
- 헤더 서식(굵게·채움 `1F4E79`·흰 글씨·가운데·줄바꿈)·틀 고정 `A2`·본문 줄바꿈/상단 정렬/thin
  테두리를 재현한다.
- 데이터 행 다음에 빈 행 1 + 범례 행 1 을 쓴다(원본 레이아웃). 범례 문구는 이 프로젝트의 것
  ("S·F=입력 점수, 위험도=수식(S×F). hazop-copilot FR-07 생성물.")이며 원본 범례를 복사하지
  않는다(원본 범례는 NH3 QRA 과업 고유 문맥이다).

**수용 기준**: 골드셋 34건 입력 시 재로딩한 시트가 37행×12열, 헤더 12개 문자열 일치,
J2~J35 가 각각 `=H{r}*I{r}`, 열 너비 11개 일치, I 열 너비 미설정.

### R-03 xlsx `평가기준` · `스크리닝` 시트 (포함 결정)

PRD FR-07 과 `domain.md` §3 은 두 시트를 언급하지 않는다. 이 spec 은 다음과 같이 **결정**한다:

- **`평가기준` 시트: 포함.** `data/gold/rating_scale.json` 에서 원본과 같은 3열 레이아웃
  (S 5행 · F 5행 · 빈 행 · 위험도 구간 3행 · 빈 행 · 주석)으로 재구성한다. 데이터가 이미
  있고 결정적이며, 워크시트의 S·F 숫자를 읽는 사람에게 등급 정의가 함께 있어야 한다.
- **`스크리닝` 시트: 5×5 매트릭스만 포함.** 제목 1행 + `S＼F` 헤더 + S5~S1 5행, 셀은 원본과
  같은 `COUNTIFS(HAZOP워크시트!$H$2:$H${last}, s, HAZOP워크시트!$I$2:$I${last}, f)` 수식이다
  (`last` = 마지막 데이터 행). 시나리오 선정 논리표·미채택 사유표·판정문은 **제외**한다 —
  QRA 과업의 분석 결과이지 이탈 목록에서 유도되는 것이 아니다.

따라서 산출물은 "원본과 동일한 12열 양식 + 등급표 + 스크리닝 매트릭스" 이며, 시나리오 선정표를
포함한 "원본과 동일한 통합문서" 라고 서술하지 않는다.

**수용 기준**: 시트 이름 순서가 `["HAZOP워크시트", "평가기준", "스크리닝", "근거", "신뢰도"]`.
`평가기준` 18행×3열이고 B2..B6 = 1..5, `스크리닝` B3 수식이 `COUNTIFS(` 로 시작하고
`$H$2:$H$35` 를 포함한다(골드셋 34건 기준).

### R-04 xlsx `근거` 시트

**The system shall** 헤더 `No · source_id · doc_title · locator · quote` 를 쓰고, 각 레코드의
`evidence[]` 원소를 한 행씩 쓴다(이탈 No 반복).

- **현 시점에는 항상 비어 있다.** FR-03 은 `evidence=[]` 고정이고 골드셋에는 필드가 없다.
- 데이터가 0행이면 A2 에 안내 문구 1행을 쓴다:
  `"근거 없음 — FR-04(evidence-citation) 미완료. evidence[] 가 채워지면 이 시트가 자동으로 채워진다."`
  빈 시트를 결함으로 오독하지 않게 하기 위해서다.
- evidence 원소는 dict 로 취급하고 위 4개 키를 `.get()` 으로 읽는다(FR-04 가 스키마를 확정하기
  전이므로 필수 키를 강제하지 않는다).

**수용 기준**: 골드셋·FR-03 mock 결과 모두에서 `근거` 시트가 2행(헤더 + 안내)이다.
evidence 1건을 넣은 레코드를 주면 안내 행이 사라지고 데이터 1행이 쓰인다.

### R-05 xlsx `신뢰도` 시트

**The system shall** 헤더 `No · confidence · 사유` 를 쓰고 레코드마다 1행을 쓴다.

| confidence | 표기 | 사유 |
|---|---|---|
| `"grounded"` | grounded | 근거 인용 첨부·검증 통과 (FR-04/FR-06) |
| `"inferred"` | inferred | 모델 추론 — 근거 미첨부(FR-04)·검증 미수행(FR-06) |
| `"review"` | review | 스키마 검증 2회 실패 행 — 사람 검토 필요 |
| `None` | 미부여 | 입력에 confidence 필드 없음(골드셋 등 사람 작성 레코드) |

- **현 시점에 FR-03 결과는 전 행 `inferred` 단일값이다.** 등급 판정은 FR-06 소관이며 이 시트는
  판정 결과를 표시만 한다.

**수용 기준**: FR-03 mock 결과 입력 시 B 열이 전부 `inferred`; 골드셋 입력 시 전부 `미부여`.

### R-06 신뢰도 리포트 JSON

**The system shall** `dict` → JSON(UTF-8, `ensure_ascii=False`, 들여쓰기 2) 을 쓴다. 필드:

| 필드 | 값 | 비고 |
|---|---|---|
| `generated_by` | `"hazop-copilot FR-07"` | |
| `generated_at` | 주입 인자 또는 `null` | R-08 |
| `record_count` | 정수 | |
| `nodes` | 노드 문자열 정렬 목록 | |
| `confidence_distribution` | `{grounded, inferred, review, unassigned}` 건수 | `unassigned` = `None` |
| `evidence_attachment_rate` | evidence ≥ 1 인 레코드 비율, **전 레코드 evidence 가 비면 `null`** | 0 은 측정 결과처럼 읽히므로 FR-04 전에는 `null` |
| `matrix_coverage` | 호출자가 `(expected_cells, judged_cells)` 를 주면 `{expected, judged, ratio}`, 아니면 `null` | FR-03 `HazopGenerator` 의 관측값. 골드셋에는 없음 |
| `risk_distribution` | `{"높음": n, "중간(ALARP)": n, "낮음": n}` — `rating_scale.json` 구간 15~25 / 8~14 / 1~7 | |
| `sf_matrix` | 5×5 건수, `sf_matrix[S][F]` 문자열 키 `"1".."5"` | `스크리닝` 시트와 같은 수 |
| `pending` | 아직 못 채운 필드와 담당 FR 의 사전 | 예: `{"evidence_attachment_rate": "FR-04", "matrix_coverage": "FR-03 생성기 관측값 필요"}` |

**수용 기준**: 골드셋 34건 → `record_count=34`, `confidence_distribution.unassigned=34`,
`evidence_attachment_rate=null`, `risk_distribution` 합 = 34, `sf_matrix` 총합 = 34.

### R-07 LOPA 초안 Markdown — **A안(정량 자리표시자) 채택**

세 안 중 **A안**을 채택한다. 이유: 이 프로젝트가 가진 것은 정성 등급 S·F(1~5)뿐이고,
`domain.md` §4.3 은 "정량 빈도·확률은 Phase 2 FTA·ETA 에서 문헌치로 산정하며 스크리닝 F 등급과
혼용하지 않는다"고 못 박는다. S×F 에서 IEF·PFD 를 유도하는 C안은 이 규칙 위반이며 만들어 낸
숫자가 환각이다(NFR-03). B안(제외)은 PRD FR-07 문면과 어긋나 PRD 개정이 필요하다.
사용자 결정 2026-09-11: A안.

**The system shall** 위험도 상위 N개(기본 5, 동률은 No 오름차순) 이탈에 대해 다음을 쓴다:

- 문서 머리 고정 문구: **"정성 스크리닝(S×F) 기반 초안. IEF·PFD·TMEL·RRF 등 정량값은
  미산정이며 문헌 근거(FR-04/FR-05) 확보 전에는 채우지 않는다."**
- 시나리오별 절: 이탈 정보(No·노드·가이드워드·이탈·S·F·위험도·판정 구간) → 시나리오 서술
  (원인 → 이탈 → 결과, 레코드 텍스트만 사용) → **IE 후보** = `causes` 그대로 → **IPL 후보** =
  `safeguards_before`(기존) 와 `recommendations`(권고) 를 출처 표시하여 그대로 나열 →
  정량 표(IEF / 조건수정자 / TMEL / IPL PFD / 요구 RRF / SIL) 전 칸
  `TBD (문헌 근거 필요 — FR-04/FR-05)` → IPL 3원칙(독립성·유효성·감사가능성) **미판정**.
- IPL 후보·IE 후보는 레코드에 적힌 텍스트만 쓴다. 문서 어디에도 `/yr`, `PFD=`, `1E-` 같은
  정량 표기가 생성되지 않는다.

**수용 기준**: 골드셋 입력 시 상위 5건의 No 가 `risk_score` 내림차순·No 오름차순과 일치,
머리 고정 문구 존재, 정규식 `\d\s*/yr|PFD\s*=\s*\d|\d[eE]-\d` 에 매칭되는 줄 0개,
`TBD (문헌 근거 필요` 가 시나리오 수 × 6 회 이상 등장.

### R-08 오프라인·재현성

**The system shall** 실행마다 바뀌는 값을 산출물에 넣지 않는다. `generated_at` 은 호출자가
문자열로 주입하며 기본값 `None`(JSON `null`, md 에는 "미기록"). UUID 를 쓰지 않는다.

**수용 기준**: 같은 입력으로 두 번 내보낸 xlsx 를 재로딩하면 전 셀 값·수식이 같고, JSON 은
바이트 동일, md 는 문자열 동일. `pytest -m "not live"` 가 자격증명 없이 통과.
